# Иллюстрации напитков (Flavor Tree v2)

Каталог v2 вырастает с 17 сортов Efes до 400+ напитков всех категорий. У 17 брендов Efes есть реальные фото
(`frontend/public/img/beers/*.webp`); у остальных — нет и быть не может: фото чужих брендов защищены
авторским правом, а генерировать «фотореалистичные» картинки мы не хотим. Поэтому каждый напиток получает
**иллюстрацию, построенную из его данных**.

## Почему иллюстрации, а не фото

- **Права.** Ни одного чужого фото и логотипа. Бокал и жидкость — наша графика.
- **Единый стиль.** 400+ карточек в одной манере (Design System v3, «премиальная тёмная гастрономия»),
  а не коллаж из этикеток разного качества.
- **Честность.** Картинка отражает реальные данные записи: цвет — из SRM/типа, пена — из стиля,
  пузырьки — из оси `carbonation`, конденсат — из температуры подачи. Ничего не «дорисовывается».

## Как выводится картинка

Рендерер: `frontend/src/app/ui/drink-art.ts` (чистая функция `drinkArtSvg(input, opts) → string`),
приоры: `data/drink_visuals.json`. Приоритет источников:

`drink.visual` → `serving.glass/ice` (каталог) → `archetypes[style.archetype]` → `families[style.family]` → `categories[category]`

| Что | Откуда |
|---|---|
| Бокал (25 типов) | архетип/семейство/категория: пилснер, вайценбокал, нонник, кружка, Willi Becher, штанге, тюльпан, снифтер, тумблер, бокалы для белого/красного/спритца, флейта, портвейн, копита, купе, мартини, рокс, хайбол, гленкерн, стопка, пиала, чашка, подстаканник, эспрессо |
| Цвет пива | SRM стиля (середина диапазона BJCP) → стандартная таблица SRM→sRGB (1..40) с интерполяцией; мутные стили (haze) пастельнее |
| Цвет вина/коктейлей/крепкого | по типу: белое/розовое/оранжевое/красное/креплёное; коктейли — по рецепту (кампари, апероль, бурбон…) |
| Пена | высота и цвет из стиля: вайцен высокая белая, стаут кремово-бежевая, лагер средняя белая; сидр/вино — без пены |
| Пузырьки | `sensory.carbonation` (игристое — мелкий бисер), позиции — детерминированно из хэша `id` |
| Лёд | `none | large_cube | cubes | crushed` (enum `serving.ice` спецификации) |
| Гарнир | архетип; для незнакомых коктейлей — из `aroma_tags` (citrus → лимон/лайм, bitter_orange → цедра, cherry, mint…) |
| Конденсат | подача ≤ 8 °C |
| Пар | подача ≥ 50 °C |
| Кромка | `salt | sugar` (маргарита) |

Каждая запись в `drink_visuals.json` несёт `anchor` — откуда взято значение
(например, `BJCP 4A Munich Helles: SRM 3–5 → 4 → #FFBF42; кружка (Maß)`).

Контуры рисуются `currentColor` с прозрачностью, поэтому одна и та же картинка одинаково читается
на тёмной (#0B0806) и светлой (кремовой) теме — хост задаёт `color`.

## Использование

```html
<ft-drink-art [drink]="d" [size]="96" />              <!-- d — запись data/drinks.json -->
<ft-drink-art [drink]="d" [size]="200" [animate]="true" [preferPhoto]="true" />
```

`frontend/src/app/ui/drink-art.component.ts` — standalone, OnPush. `preferPhoto` показывает реальное `image`,
если оно есть; `animate` включает лёгкую анимацию пузырьков/пара (учитывает `prefers-reduced-motion`).

## Как заменить на реальное фото

Когда есть права на снимок (собственные бренды, договор с дистрибьютором), добавьте в запись напитка поле
`"image": "img/beers/<id>.webp"` и положите файл в `frontend/public/img/beers/`. Компонент с `preferPhoto`
покажет фото; иллюстрация останется резервом (и используется там, где фото не нужно — в списках и подсказках).

## Точечная правка картинки

Если у конкретного напитка цвет/бокал отличаются от стилевого приора, добавьте в запись `visual`:

```json
"visual": { "srm": 6, "glass": "mug", "foam": { "height": 0.6 }, "garnish": ["lemon_wheel"], "ice": "cubes" }
```

Любое поле `visual` побеждает приор. Незнакомый архетип не ломает рендер: срабатывает фолбэк по
`style.family`, затем по `category`.

## Галерея

`node frontend/scripts/drink-art-gallery.mjs` собирает `docs/drink-art/gallery.html` (все 57 архетипов,
25 бокалов, фолбэки по семействам и категориям, а при наличии `data/drinks.json` — весь каталог) и снимает
`gallery-dark.png` / `gallery-light.png` тем же Chrome, что `screenshots.mjs`. `--no-shots` — только HTML.
В репозитории лежат уменьшенные превью `gallery-dark.webp` и `gallery-light.webp`; полноразмерные PNG и HTML
генерируются заново и в git не попадают (`.gitignore`).
