# Фотографии блюд

Каждое блюдо в приложении показывается с настоящей фотографией вместо эмодзи. Здесь описано, откуда берутся снимки, на каких условиях мы их используем, как они подписываются и как заменить фото.

## Итог

- Блюд с фото: **127** (источники: Wikimedia Commons — 127).
- Лицензии: CC BY-SA 4.0 — 52; CC BY 2.0 — 27; CC0 1.0 — 15; CC BY-SA 2.0 — 12; CC BY-SA 3.0 — 11; CC BY 4.0 — 8; Public domain — 2.
- Файлы: 254 WebP, всего 16376 КБ (в среднем 98 КБ на 1200×900 и 30 КБ на 480×480; смягчено при кодировании: 22; единственный файл выше цели — okroshka, 157 КБ).
- Без фото: 6 блюд (список ниже).

Контактные листы для просмотра всего набора целиком: `docs/dish-photos/contact-sheet-1.png` … `contact-sheet-6.png` (по 24 фото на лист, подписаны id блюд). В git они не хранятся (16 МБ) — пересобираются командой `python3 scripts/fetch_dish_photos.py sheets` из кэша, без сети.

## Откуда фото

1. **Wikimedia Commons** — основной источник. Поиск через API (`action=query&generator=search`, пространство файлов) по английскому и русскому названию блюда, по категории Commons и по «depicts» из Викиданных. Для каждого файла берётся `extmetadata`: автор, лицензия, ссылка на лицензию, ограничения.
2. **Openverse** — вспомогательный источник. Используется только провайдер WordPress Photo Directory (CC0): у него доступны оригиналы полного размера. Flickr через Openverse не используется — API отдаёт не больше 1024 px по длинной стороне, этого мало.

Итоговый набор целиком собран с Wikimedia Commons: там нашлись подходящие снимки для всех блюд, для которых фото вообще есть в свободном доступе.

## Какие лицензии допустимы и почему

Проект показывается публично и от имени бренда, поэтому правило строгое. Берём только:

- **CC0** и **Public domain** — можно использовать без условий;
- **CC BY** (любая версия) — нужно указать автора и лицензию;
- **CC BY-SA** (любая версия) — то же плюс производная работа распространяется на тех же условиях.

Не берём: CC BY-NC (запрет коммерческого использования — наш продукт коммерческий), CC BY-ND (запрет изменений — мы кадрируем и корректируем цвет), GFDL-only, «fair use», файлы без указанной лицензии, а также фото с водяными знаками, читаемыми надписями и логотипами, упаковкой брендов и узнаваемыми лицами. Такие кандидаты отбрасываются автоматически по метаданным (лицензия, ограничения) и вручную при просмотре.

Ещё одно ограничение — разрешение: короткая сторона кадра после кадрирования не меньше 900 px оригинала, иначе на экране с высокой плотностью пикселей фото будет мыльным.

## Как показывается атрибуция

- В `data/dish_photos.json` для каждого блюда хранятся: `source_page` (страница файла на Commons), `original_url`, `author`, `license`, `license_url`, `attribution_ru` (готовая подпись вида «Фото: Автор, CC BY-SA 4.0, Wikimedia Commons · кадрировано, цветокоррекция»), `changes` (что мы сделали с файлом — требование CC BY/BY-SA), `derivative_license` (для CC BY-SA — лицензия нашего производного файла), `fetched_at`.
- Компонент `<ft-dish-photo>` (`frontend/src/app/ui/dish-photo.component.ts`) умеет показывать подпись прямо на фото (`[credit]="true"`): мелко, приглушённо, со ссылкой на страницу источника.
- Страница «Источники фото и данных» (`frontend/src/app/pages/credits/credits.page.ts`) перечисляет все фото с автором, лицензией и ссылками, сгруппированные по кухням. Это основной способ выполнить требование об атрибуции: подпись под каждой карточкой в интерфейсе была бы шумом, а страница с полным списком доступна из любого места приложения.

## Обработка

Скрипт `scripts/fetch_dish_photos.py` для каждого выбранного файла:

1. заново запрашивает метаданные и проверяет лицензию (устаревшие или изменившиеся лицензии остановят сборку);
2. скачивает превью 2560 px или оригинал, если для кадра нужно больше пикселей;
3. кадрирует по заданной точке интереса и масштабу (или по явной рамке) в 4:3 и 1:1;
4. применяет одну и ту же лёгкую «проявку» ко всем фото — чуть теплее, контраст +6 %, насыщенность +4 %, мягкая виньетка 10 %, лёгкая резкость. Параметры записаны в `_meta.grade` в JSON. Ничего, что искажало бы вид еды, не применяется;
5. сохраняет `frontend/public/img/dishes/<id>.webp` (1200×900) и `<id>-sq.webp` (480×480) без метаданных, WebP качество 78. Если файл больше 130 КБ / 40 КБ, качество снижается ступенями до 62; если и этого мало (очень мелкая фактура — зелень, слоёное тесто, соль на брецеле), изображение слегка смягчается и кодируется заново с более высоким качеством — так файл меньше, а вид лучше, чем при качестве ниже 56. Итоговое качество и признак смягчения записаны в JSON (`webp_quality`, `softened`).

Ответы API и скачанные файлы кэшируются в `~/.cache/flavortree-dish-photos` (или `$FT_PHOTO_CACHE`), повторный запуск не ходит в сеть. Все запросы идут последовательно с паузой и с User-Agent проекта.

## Как заменить фото

1. `python3 scripts/fetch_dish_photos.py candidates <id>` — соберёт кандидатов (лицензия и размер уже проверены) и положит лист с превью в `<кэш>/candidates/<id>.jpg`, рядом JSON с точными именами файлов.
2. Выбрать файл, вписать его в таблицу `SELECTION` в скрипте: `"<id>": P("commons", "File:….jpg", focus=(x, y), zoom=0.9)`. `focus` — точка интереса в долях кадра, `zoom` — доля от максимально возможного кадра; для точного кадра можно задать `box=(x0, y0, x1, y1)`, для квадрата — `sq_focus`/`sq_zoom`/`sq_box`.
3. `python3 scripts/fetch_dish_photos.py preview <id>` — покажет рамки 4:3 и 1:1 поверх фото (`<кэш>/preview/<id>.jpg`).
4. `python3 scripts/fetch_dish_photos.py build <id>` — соберёт webp и обновит `data/dish_photos.json`; `… sheets` пересоберёт контактные листы.
5. `python3 scripts/fetch_dish_photos.py check` — перепроверит лицензии всех выбранных файлов без кэша (полезно раз в несколько месяцев: авторы иногда меняют лицензию, файлы удаляют).

Новое блюдо: добавить запись в `QUERIES` (английское и русское название, категория Commons) и дальше по шагам выше. Если у блюда нет фото, компонент показывает плитку с эмодзи — ничего ломать не нужно.

## Блюда без фото и почему

- **Жая** (`zhaya`) — На Commons и в Openverse нет свободных фото жая (вяленый конский окорок); подменять похожей нарезкой не стали.
- **Шужык** (`shuzhyk`) — Свободные фото есть только для турецкого/армянского суджука — это другой продукт, не казахский шужык.
- **Иримшик** (`irimshik`) — Свободных фото иримшика не найдено (поиск по irimshik / ірімшік / казахская кухня даёт только другие сыры).
- **Куырдак** (`kuyrdak`) — Единственное свободное фото (1280×960, CC BY-SA 2.0) — казан с рукой повара в кадре; ниже порога качества и разрешения.
- **Куырдак из печени** (`kuyrdak-liver`) — См. kuyrdak — подходящего фото нет.
- **Ганфан** (`ganfan`) — Фото ганфана (дунганская кухня) в свободных источниках нет.

Подменять эти блюда похожими (например, турецким суджуком вместо шужыка) мы не стали: подпись под фото должна быть честной. Для них в интерфейсе остаётся эмодзи-плитка. Когда появится собственная фотосъёмка, снимки добавляются той же таблицей `SELECTION` (источник `local` пока не реализован — проще всего положить файл на Commons под CC BY-SA или добавить ветку в `resolve()`).

## Что ещё стоит знать

- Кумыс, айран и шубат: единственный свободный снимок в пиале — любительский кадр двух чашек на скатерти, для карточек напитков он слишком слабый, поэтому папка `img/dishes/drinks-traditional/` пуста.
- Несколько фото сняты в конкретных заведениях (это видно по именам файлов на Commons); в подписи указывается только автор, как требует лицензия.
- Файлы под CC BY-SA: наши производные webp распространяются на условиях той же лицензии, это отмечено в JSON (`derivative_license`).
