# ИИ-сомелье Flavor Tree

Два входа для гостя: **текстовый вопрос** («что взять к мантам, не люблю горькое») и **фото блюда** (AI Food Scanner — приоритет №1 по CustDev, `research.md` §8.1).

## Принцип: ИИ переводит, движок решает

```
гость (текст / фото)
   │
   ▼  Claude (claude-opus-5, структурированный JSON, строгая схема)
┌───────────────────────────────────────────────────────────┐
│ kind: dish | clarify | chat                                │
│ dish: { matched_slug | null, taste, weight, fat, cooking,  │
│         heat 0..1, tags[], confidence }                    │
│ occasion: hot | evening | party | gourmet | null           │
│ bitter_pref: −1..1                                         │
└───────────────────────────────────────────────────────────┘
   │
   ▼  Движок подбора (15 правил, детерминированный, паритет Python ↔ TS)
   top-3 пары · только из карты заведения, если гость в баре · с ценами
   │
   ▼  Claude (объяснение словами сомелье, 2–4 предложения, без markdown; на языке гостя — ru / kk / en)
ответ гостю + кнопка «Заказать» + ссылка «Полный разбор по правилам»
```

Почему так, а не «спросить у GPT, какое пиво»:
- **Объяснимость.** Каждая рекомендация раскладывается по правилам (интенсивность, очищение жира, острота, соль, мосты по ароматам, вердикт сомелье). Жюри и бар видят, *почему*.
- **Контроль ассортимента.** ИИ физически не может посоветовать сорт, которого нет на кранах: список разрешённых сортов передаётся движку, а не модели.
- **Стабильность.** Одинаковое блюдо → одинаковые пары. Модель лишь распознаёт и объясняет.
- **Кэш промпта.** Каталог блюд и сортов лежит в системном промпте с `cache_control` → повторные запросы дёшевы. Язык гостя этот кэш не дробит — см. «Язык гостя».
- **Язык не трогает выбор.** На казахском и английском модель переводит только слова; сорта, порядок, оценки и цены — всегда от движка.

## Где работает

| Где | Файл | Когда используется |
|---|---|---|
| Vercel Function | `frontend/api/ai.ts` → `frontend/api/_lib/sommelier.ts` | Демо на Vercel без Django. Импортирует **тот же TS-движок** и копию `data/*.json` (`npm run build` синхронизирует через `scripts/sync-data.mjs`). |
| Django | `backend/api/ai.py` → `POST /api/ai/` | Прод с бэкендом: цены и стоп-лист берутся из БД по `venue.slug`. |
| SPA | `core/ai.service.ts`, `pages/scan/scan.page.ts`, `ui/sommelier-chat.component.ts` | Камера, чат, кнопки на главной / подборе / гостевом меню. |

Адрес выбирается в `core/config.ts`: `window.FT_AI_URL` → иначе `API_URL + '/ai/'` → иначе `/api/ai` (Vercel).

## Контракт

`POST /api/ai` (Vercel) или `POST /api/ai/` (Django), JSON:

```jsonc
{ "mode": "ask",    "messages": [{"role":"user","content":"что к казы в жару?"}],
  "venue": { "slug": "efes-beer-garden-almaty", "name": "…", "beers": ["13-region", …],
             "prices": {"13-region": 1750}, "volumes": {"13-region": "0.5 л"}, "currency": "₸" },
  "occasion": null, "bitter_pref": 0, "dna": null, "locale": "kk" }

{ "mode": "vision", "image": {"media_type":"image/jpeg","data":"<base64>"}, "messages": [], "venue": …, "locale": "en" }
```

`locale` — необязательное: `"ru"` | `"kk"` | `"en"`. Нет поля или любое другое значение → `"ru"`.

Ответ:

```jsonc
{ "ok": true, "kind": "picks",
  "reply": "К казы берите 13 Регион — …",
  "dish": { "name": "Казы", "slug": "kazy", "emoji": "🥩", "spec": {…}, "confidence": 0.92 },
  "picks": [{ "beer_id": "13-region", "name": "13 регион", "score": 91, "match_label": "Cleanse · очищение",
              "why": "Горечь и пузырьки смывают жир", "reasons": [...], "warnings": [], "price": 1750, "volume": "0.5 л" }],
  "route": "/pair/kazy?occasion=hot", "occasion": "hot", "locale": "ru", "usage": { "input": 2310, "output": 260, "calls": 2 } }
```

`locale` в ответе — язык, который реально применён (после приведения к `ru | kk | en`); он есть во всех успешных ответах, включая `clarify` и `chat`.

`kind: "clarify"` — модель задала уточняющий вопрос (в `reply`), `kind: "chat"` — ответ на общий вопрос о пиве. Ошибки: `{ok:false, error}` со статусами 400 / 413 / 429 / 502 / 503 («ИИ не настроен»).

## Язык гостя (ru / kk / en)

Что на каком языке:

| Поле | ru | kk / en |
|---|---|---|
| `reply` (подтверждение, уточняющий вопрос, ответ в `chat`, объяснение сомелье) | как раньше | пишет модель на языке гостя |
| `picks[].why`, `reasons`, `warnings` | русский текст движка | перевод русского текста движка, получен тем же вызовом «объяснение» |
| `picks[].match_label` | подпись движка (`Cleanse · очищение`) | статичная карта по `PairingType` в коде: kk — `Cleanse · тазарту`, en — `Cleanse`; модель не участвует |
| готовые фразы (отказ модели, пустое уточнение, «в карте нет подходящего сорта») | как раньше | статичные строки в коде |
| `beer_id`, `name`, `score`, `match_type`, `price`, `volume`, порядок пар, `route`, `dish.spec` | движок | движок — от языка не зависят |
| `dish.name` | каталог или как назвал гость | каталог (по-русски) или как назвал гость |
| ошибки `{ok:false, error}` | по-русски | пока по-русски |

**Кэш промпта.** Кэш Anthropic — это совпадение префикса байт-в-байт до блока с `cache_control`. Поэтому язык в системный промпт **не подставляется**: `system[0]` (роль, правила, каталоги, `cache_control`) одинаков для всех языков, а указание языка уходит вторым блоком `system[1]` без `cache_control` — он стоит уже после точки кэша и на попадание не влияет. Для `ru` второго блока нет вовсе: запрос к модели остался ровно таким, каким был до локалей. Схема ответа фазы «понять блюдо» тоже одна на все языки, так что самый дорогой префикс — каталог на несколько тысяч токенов — общий для ru / kk / en: гость на казахском попадает в кэш, прогретый гостем на русском. Указание идёт именно system-блоком, а не текстом в реплике гостя, чтобы гость не мог подменить его своим сообщением.

Оговорка про вторую фазу: для kk/en вызов «объяснение» идёт с `output_config.format` (JSON-схема), а для ru — без неё. `system[0]` там тоже одинаков, но формат вывода может вести отдельную запись кэша; к тому же сам `SYSTEM_NARRATE` короткий — по оценке меньше минимального кэшируемого префикса `claude-opus-5` (512 токенов), то есть там кэш, скорее всего, не срабатывает ни на одном языке. Это оценка, а не замер: проверять по `usage.cache_read_input_tokens` в ответе API (поле `usage.input` в нашем ответе — только некэшированный остаток).

**Перевод текстов пар.** Для kk/en в brief второго вызова добавляются `beer_id` и `why`, а ответ запрашивается строгим JSON:

```jsonc
{ "reply": "…", "picks": [{ "beer_id": "13-region", "why": "…", "reasons": ["…"], "warnings": ["…"] }] }
```

Из него берутся только `reply` и три текстовых поля — и только если `beer_id` совпали с парами движка один в один и в том же порядке, а причин и предупреждений столько же, сколько дал движок, и все строки непустые. Любое расхождение, оборванный или неразборчивый JSON, отказ модели → у пар остаётся русский текст движка, запрос не падает (если `reply` из JSON годен, он используется; иначе остаётся фраза-подтверждение первой фазы — она уже на языке гостя). Лишние поля в JSON (`score`, `price`, `name`…) игнорируются: поменять выбор модель не может. Ответ на kk/en длиннее (перевод ~10–15 коротких строк), поэтому `max_tokens` у этого вызова 3000 вместо 700; выходных токенов больше — значит, и ответ дольше русского (на живом ключе не замерялось).

**Казахский.** Модель получает указание писать на естественном современном казахском кириллицей — коротко, тепло, без markdown и без кальки с русского; названия блюд можно оставлять так, как их написал гость, названия сортов не переводятся.

Тексты указаний, статичные фразы и схема в `sommelier.ts` и `ai.py` совпадают дословно — это проверяет `test_prompts_mirror_typescript`.

## Настройка

- **Vercel:** Project → Settings → Environment Variables → `ANTHROPIC_API_KEY`. Функция объявлена в `vercel.json` (`maxDuration: 60`). Rewrite SPA исключает `/api/*`.
- **Django:** `export ANTHROPIC_API_KEY=…` перед `runserver`/gunicorn. Без ключа — 503 с текстом, интерфейс показывает подсказку.
- Модель — `claude-opus-5`; фаза распознавания идёт с `effort: medium` (фото) / `low` (текст), объяснение — `low`. Фото ужимается на клиенте до 1024 px (JPEG 0.82) — ~1–1.5k токенов на снимок.
- Стоимость одного «сфоткал → получил ответ»: порядка 3–4k входных (из них каталог в кэше) + ~300 выходных токенов.
