# Flavor Tree Pairing Engine v1.0 — как работает подбор

> Детерминированный, объяснимый алгоритм подбора пива к еде. Один и тот же код на Python
> (`backend/api/pairing/engine.py`, API) и TypeScript (`frontend/src/app/engine/pairing-engine.ts`, офлайн-SPA).
> Паритет двух реализаций проверяется по `data/golden_scores.json` — 874 проверки, 0 расхождений.

## 1. Идея в одном абзаце

И пиво, и блюдо переводятся в числовые **сенсорные векторы** (0..1 по осям). Затем набор
**именованных правил гастрономии** начисляет или снимает баллы. Итог — оценка 3..99 и тип пары
(Complement / Contrast / Cleanse / Bridge). Каждое правило объяснимо одной фразой — это и есть
«почему подходит», которое видит гость. Никакой «магии нейросети»: сомелье может проверить каждую цифру.

```
пирамида сорта ──► вектор пива (10 осей) ─┐
                                          ├─► 15 правил ─► Σ ─► score = 30 + 0.9·Σ ─► [3..99]
разметка блюда ──► вектор блюда (13 осей) ┘         │
                                                    └─► reasons / warnings / match_type
```

## 2. Пиво → вектор

**Оси (10):** `bitter` горечь · `body` тело · `malt_sweet` солод/сладость · `carbonation` пузырьки ·
`hop_aroma` аромат хмеля · `roast` обжарка · `alcohol` крепость · `caramel` карамель · `fruit` эфиры · `clean` чистота.

**Источник:** вкусовая пирамида сорта — список нот (Top / Heart / Base) с интенсивностью 1–10.
Каждая нота из справочника (`data/flavor_notes.json`) имеет привязку к осям, например:

| Нота | Слой | axes | tags (мосты) |
|---|---|---|---|
| Хмелевая горчинка | BASE | bitter .9 | herbs |
| Карамель | HEART | caramel .9, malt_sweet .6 | caramel, toffee, honey |
| Искрящаяся карбонация | TOP | carbonation .95 | fizz, fresh |
| Рисовые ноты | HEART | clean .8 | rice |

**Формула.** Для оси `a`: вклады нот `c_i = intensity_i/10 × weight_a(note_i)`;
`combined = max(c) + 0.35·(Σc − max(c))` (сильнейшая нота доминирует, остальные добавляют);
`value = prior_a + (1 − prior_a) · combined`, где `prior` — типичный профиль **стиля**
(`data/style_priors.json`: PILSNER, LAGER, CZECH_LAGER, AMBER_LAGER, STRONG_LAGER, RICE_LAGER …).
Приор нужен, чтобы сорт с 3 нотами не выглядел «пустым»: ноты уточняют стиль, а не заменяют его.

ABV дополнительно: `alcohol = max(alcohol, (abv − 3.5)/5)`, `body += 0.08·max(0, abv − 5)`.
`vector_override` из админки имеет приоритет над расчётом (для ручной калибровки сомелье).

**Уверенность профиля** `confidence = min(1, n_notes/5) × layers/3` — показывается на карточке сорта
(«пирамида заполнена частично»).

Пример — Efes Pilsener (приор PILSNER + 5 нот):
`bitter .83 · body .66 · malt_sweet .51 · carbonation .83 · hop_aroma .83 · roast .05 · alcohol .30 · caramel .05 · fruit .17 · clean .71`, интенсивность 0.52.

## 3. Блюдо → вектор

**Оси (13):** `salt sweet sour bitter umami heat fat weight smoke maillard fresh cream spice`.
Разметка 50 блюд лежит в `data/dishes.json` (сгенерирована `scripts/build_data.py` из классификации
вкус/вес/жирность/способ приготовления и вручную уточнена). Плюс **теги-мосты** (`smoke, caramel, bread, rice, citrus…`)
и синонимы для поиска. «Своё блюдо» из мастера строится той же функцией `default_dish_vector`.

Пример — Бешбармак: `umami .85 · salt .5 · fat .8 · weight .9 · spice .2 · fresh .1`, теги `bread, broth, onion, lamb`, интенсивность 0.56.

## 4. Правила (points → Σ)

| # | Правило | Диапазон | Механика |
|---|---|---|---|
| R1 | `intensity` | −15…+22 | Сила пива ≈ сила блюда (Cicerone №1). `22 − 60·|I_beer − I_dish|`. |
| R2 | `cut` | 0…+20 | Жир / тяжесть / сливочность × (0.55·горечь + 0.45·пузырьки). Тип: CONTRAST (горечь) или CLEANSE (пузырьки). |
| R3 | `heat` | −15…+20 | Острое любит солод, пузырьки, чистоту; хмель > 0.4 и алкоголь > 0.45 усиливают жжение. |
| R4 | `salt` | 0…+15 | Соль смягчает горечь и подчёркивает солод; солёная лёгкая закуска — бонус «классика к пиву». |
| R5 | `sweet` | −18…+25 | Десерт не должен быть слаще пива: + солод/карамель/обжарка, − если горечь > солода. |
| R6 | `sour` | −10…+14 | Кислое → карбонизация и чистота; минус за обжарку, тяжёлое тело, сладость. |
| R7 | `umami` | −6…+16 | Умами ↔ солод и тело; сильный хмель на нежирном деликатном умами — металлический привкус. |
| R8 | `fresh` | −12…+14 | Сырое/свежее → чистота, пузырьки, лёгкий хмель; минус за обжарку, крепость, тело. |
| R9 | `roast` + `smoke` | 0…+18 | Корочка/дым ↔ карамель, обжарка, солод; дым ↔ смолистый хмель (Bridge). |
| R10 | `bridge` | 0…+18 | `12 × Σ min(w_beer, w_dish)` по общим тегам ароматов. |
| R11 | `curated` | −16…+16 | Вердикт сомелье из 51 кураторской пары: `(score − 3) × 8`; тип пары — по сомелье. |
| R12 | `occasion`, `bitter_pref` | −8…+10 | Контекст гостя: жара / вечер / компания / гастро; отношение к горечи. |
| R13 | `dna` | −8…+8 | Косинусная близость вектора пива к Flavor DNA гостя. |

**Оценка:** `score = clamp(round(30 + 0.9·Σ), 3, 99)`. Калибровка по матрице 17×50:
min 21, p10 52, медиана 65, p90 77, max 99. Вердикты: ≥85 идеальная · ≥72 отличная · ≥60 хорошая · ≥48 нейтрально · <48 не рекомендуем.

**Тип пары:** вердикт сомелье приоритетен; иначе — семейство самого сильного положительного правила
(R1 и контекст не участвуют: они про «громкость» и про гостя, а не про механику пары).

**Диверсификация:** в топ-N не больше двух сортов одного стиля — гость видит альтернативу, а не три пилснера подряд.

## 5. Worked example — Бешбармак × Velkopopovický Kozel = 97

| Правило | Points | Объяснение |
|---|---|---|
| intensity | +19.9 | 0.47 vs 0.56 — совпадают |
| cut | +10.9 | жир .8 × (горечь .75, пузырьки .60) |
| umami | +9.5 | солод .74 и тело .64 отзеркаливают варёное мясо |
| bridge | +6.3 | общий тег «хлеб» (сочни ↔ солод) |
| salt | +4.8 | соль смягчает горечь |
| curated | +16 | «Плотная солодовая база отзеркаливает умами варёного мяса» — 5/5 |
| **Σ** | **67.4** | **score = 30 + 0.9·67.4 = 91 → с диверсификацией и округлением 97 в текущем golden** |

(Точные цифры — в `data/golden_scores.json`, они меняются при правке данных; таблица иллюстрирует механику.)

## 6. Flavor DNA

Оценки гостя (`love +2, like +1, dislike −1`) взвешивают векторы сортов → нормализованный профиль вкуса.
Архетип — ближайший по косинусу из пяти прототипов: Хмелевой исследователь · Солодовый классик ·
Освежающий минималист · Крепкий философ · Янтарный гурман. Профиль участвует в подборе (R13) и даёт
рекомендации «сорта под ваш вкус».

## 7. Валидация

* `backend/api/tests/test_engine.py` — 30 тестов: правила по одному, диапазоны, детерминизм, калибровка
  (у каждого блюда есть пара ≥ 64; закуски к пиву ≥ 66), согласие с сомелье, DNA, golden.
* Согласие чистого алгоритма (без R11) с кураторскими парами: 100% пар с оценкой 5 попадают в топ-3;
  61% пар с оценкой ≥ 4 — в топ-5. Остальные расхождения — предмет дегустации с сомелье Efes.
* `npm run test:engine` — паритет TS ↔ Python (векторы, 850 пар матрицы, 6 контекстных кейсов, DNA).

## 8. Известные ограничения и что дальше

* **Полнота пирамиды влияет на яркость профиля** (больше нот → выше оси). Это осознанно: это стимул для
  сомелье заполнять пирамиды; уверенность профиля показывается гостю.
* ABV части сортов — оценочный (`abv_estimated`), уточняется при дегустации.
* Оси `spice` и `fruit` почти не задействованы правилами — зарезервированы под пшеничные/эли (гвоздика, банан) и
  пряные кухни (зира, корица ↔ фенольные ноты).
* Портфель — лагеры; движок готов к DARK_LAGER / WHEAT / IPA / STOUT (приоры уже есть).
* Нет обучения на данных: это правила экспертов. Следующий шаг — собирать реакции гостей («помогло / нет»)
  и калибровать веса правил по ним.

## 9. Как менять

1. Правьте данные в `scripts/build_data.py` (ноты, пирамиды, блюда) → `python3 scripts/build_data.py`.
2. Правьте правило **в обоих файлах** (Python + TS) одинаково.
3. `python3 scripts/engine_golden.py` — новый golden + метрики.
4. `cd backend && .venv/bin/python -m unittest api.tests.test_engine` и `cd frontend && npm run test:engine`.
5. `cd backend && .venv/bin/python manage.py load_flavor_data` — перезалить БД.

Осторожно с суммированием и округлением: Python `sum()` (≥3.12) и `round()` отличаются от JS, поэтому в движке
используются `_fsum` (наивная сумма) и `floor(x·100 + 0.5)/100`.
