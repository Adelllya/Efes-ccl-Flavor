# Flavor Tree — исследование дизайна (редизайн UI)

Дата: 2026-09-18. Контекст: финал OneIdea через 3 недели, партнёр Efes Kazakhstan. Основатель требует полностью переделать UI.
Ограничения: нет фотографий блюд; есть PNG/WebP бутылок 17 сортов (240×430 px, RGBA, `frontend/public/img/beers/`); каталог должен вырасти до 100+ сортов и 200+ напитков, для большинства из которых картинок не будет.

Что смотрели: `frontend/src/styles.css` (Design System v2 «Amber Glass»), `frontend/src/index.html`, `frontend/src/app/ui/icon.component.ts`, скриншоты `docs/screenshots/mobile-home.png`, `mobile-pair.png`, `mobile-pair-results.png`, `mobile-beers.png`, `mobile-venue-menu.png`, `mobile-business.png`, `mobile-admin.png`, `mobile-beer-detail.png`.

## 1. Аудит текущего UI: конкретные антипаттерны

### 1.1 Системные (видны на каждом экране)

| # | Проблема | Факт | Почему плохо |
|---|---|---|---|
| A1 | **Брендовые шрифты не содержат кириллицы.** | Проверено запросом к Google Fonts API: `Outfit`, `Plus Jakarta Sans`, `Fraunces` — 0 блоков `/* cyrillic */`. В `index.html` подключены только они. | Весь русский текст (заголовки, кнопки, чипы) рендерится системным fallback (на скриншотах — Noto Sans / Open Sans). Латиница «Flavor Tree», «Efes Pilsener», «Complement» — в Outfit. Интерфейс типографически «разъезжается»: два разных гротеска на одном экране, разная высота x, разный вес. Это главный источник ощущения «дёшево». |
| A2 | **Контраст акцентного цвета ниже нормы.** | `--amber-500 #E08A28` на фоне `#FBF7F0` = **2.51:1**; `--amber-300 #F5B942` = 1.65:1; белый текст на `--grad-amber` = 2.68:1 (на светлом конце 1.76:1). Порог WCAG AA для текста 4.5:1, для крупного 3:1. | Градиентные слова в заголовках («сегодня?», «едите?», «второе пиво») и белые подписи на янтарных кнопках («14 дней бесплатно», «Сфотографируйте») читаются хуже, чем остальной текст, хотя они и есть смысловой акцент. `--ink-4 #B8AA99` (плейсхолдеры) = 2.13:1. |
| A3 | **Эмодзи как иллюстрации и как иконки.** | В `app/` найдено 19 разных эмодзи (🍺 ×7, 📷 ×6, 🌶 ×5, 🔥 ×4, 🍖 ×4, флаги 🇰🇿🇮🇹🇯🇵…). Модель `Dish` содержит поле `emoji`. При этом в проекте уже есть `ft-icon` (39 stroke-иконок 24px) с комментарием «Без эмодзи в интерфейсных элементах» — правило нарушается. | Эмодзи рендерятся разными наборами на iOS/Android/Windows, флаги на части Android/Windows показываются как буквы «KZ». Скринридеры читают «камера с вспышкой» вместо назначения кнопки ([UX Content Collective](https://uxcontent.com/accessible-content-design-for-emojis/)). Визуально — «сайт на конструкторе». |
| A4 | **Три бренд-акцента конкурируют.** | Кремовый фон + янтарный градиент + чёрные «pill» (чипы `.on`, FAB, тосты). | Нет одного главного цвета действия: «Все» — чёрный, «Сомелье» — чёрный, «Лучшая пара» — янтарный, «Выбрать» — янтарный текст, стрелка — янтарный квадрат. |
| A5 | **Декоративный шум.** | Радиальные «свечения» на `body`, «пузырьки» (полупрозрачные кружки) на всех экранах, `.glass` blur, три уровня теней, `--r-xl 28px`. | Утяжеляет визуально, съедает GPU на дешёвых Android, не несёт информации. Тренд-отчёты 2026 фиксируют движение к чистым editorial-макетам, где идентичность несёт типографика, а не эффекты ([Figma, Web design trends 2026](https://www.figma.com/resource-library/web-design-trends/); [Kontra Agency](https://kontra.agency/top-web-design-trends-for-2026/)). |
| A6 | **Шапка обращена к жюри и к «игроку», а не к гостю.** | В шапке всегда: логотип, бейдж «0 XP / 15 XP», тумблер темы; на главной eyebrow «ONEIDEA CHAMPIONSHIP 2026 × EFES KAZAKHSTAN». | Гость у стола не знает, что такое XP; тумблер темы — настройка, не действие. На результатах XP-тост («+10 XP · Пара к «Бешбармак»») перекрывает кнопку «Назад» (`mobile-pair-results.png`, `mobile-beer-detail.png`). |
| A7 | **Два нижних слоя навигации.** | Tab bar (5 пунктов) + плавающая кнопка «Сомелье» справа над ним. На `mobile-pair.png`, `mobile-venue-menu.png`, `mobile-pair-results.png` FAB перекрывает контент карточек (название «Шужык», цену, кольцо оценки). | 6 целей в зоне большого пальца, конфликт z-index с контентом. |
| A8 | **Hero-блоки съедают первый экран.** | На `mobile-beers.png` до первой карточки ≈ 1000 px (шапка, eyebrow, H1 в две строки, lede в 3 строки, сегмент-контрол, карточка фильтров). На `mobile-venue-menu.png` коричневый hero-блок ≈ 600 px. | Исследования QR-меню: решение гость принимает в первые секунды «до скролла», категории/поиск должны быть первым, что он видит ([Dineazi, QR menu design tips 2026](https://dineazi.com/resources/qr-menu-design-tips)). |

### 1.2 По экранам

**`mobile-home.png`** — одно и то же действие предложено трижды подряд (поле поиска «Что вы едите?», карточка «Сфотографируйте блюдо», карточка «У меня есть блюдо → Выбрать»). Между ними нет иерархии. Иконка камеры — эмодзи 📷 в оранжевом квадрате. Заголовок-вопрос «Что выберешь сегодня?» + 4 строки lede: гость получает лекцию про «три слоя как в парфюмерии», прежде чем увидит поле ввода.

**`mobile-pair.png`** — «ШАГ 1 ИЗ 2» + H1 + lede + поле + повторная карточка «Или просто сфотографируйте» + ряд чипов кухонь с флагами-эмодзи. Список блюд начинается на ~970 px. Плитки блюд — эмодзи 🍖🥩 на пастельном квадрате. Чипы тегов внутри карточки («Умами», «Тяжёлое») — некликабельные, но выглядят как кнопки.

**`mobile-pair-results.png`** — самый важный экран, и ответ на нём **третий экран сверху**: сначала карточка блюда с 5 чипами в 4 строки («жирность: Высокая» — другой регистр и формат, чем «Умами»), шкалы «Вес/Умами/Соль» **обрезаны правым краем** (горизонтальный overflow), затем блок «Повод / Горечь / Оцените 3 сорта», и только потом «ЛУЧШАЯ ПАРА». На одной карточке три бейджа подряд («ЛУЧШАЯ ПАРА», «Complement · дополняет», «ВЫБОР СОМЕЛЬЕ») — инфляция бейджей, они перестают значить что-либо. Кольцо оценки скрыто за FAB.

**`mobile-beers.png`** — счётчик «17 из 17» ломается на три строки; чип «Разливное · HoRe…» обрезан; бейджи «РАЗЛИВНОЕ» (янтарный градиент) и «БУТЫЛКА» (чёрный) — разный стиль для однотипного признака; «4.5%*» со звёздочкой без сноски; изображение 240×430 растянуто в кадр 200 px с drop-shadow, на retina мылится; карточка «13 регион» показывает кружку, «Белый Медведь» — бутылку, масштаб не согласован.

**`mobile-venue-menu.png`** — аватар заведения «EB» буквами; в pill-статистике эмодзи 🍺🍽; чипы категорий — это внутренняя таксономия движка («Мясное (конская колбаса)»), а не разделы меню бара; бейдж «ХИТ» на каждом из трёх видимых блюд; повторная «Сфотографируйте» карточка внутри hero. Для QR-сценария цена и название выровнены нормально, но плитка-эмодзи слева тратит 64 px ширины впустую.

**`mobile-business.png`** — за lede-абзацем виден белый прямоугольник без отступов (артефакт фона); две CTA разной ширины друг под другом; «✔» текстовые галочки; наклонённый макет телефона с самим приложением внутри — на мобильном это только шум.

**`mobile-admin.png`** — десктопная форма, сжатая в 360 px: лейбл «СТИЛЬ (ПРИОР)» слева от селекта, «Top notes 0–3 сек» ломается, служебная надпись «API не подключён — экспортируйте JSON для data/brands.json» видна как пользовательский текст. Эмодзи 🍃🌸 перед названиями нот.

**`mobile-beer-detail.png`** — три кнопки оценки («не моё / нравится / люблю») сложены вертикально с рваной шириной; название «Efes Pilsener» ломается на две строки рядом с бутылкой; курсив Fraunces «Флагман портфеля» — латинский шрифт снова заменён fallback-курсивом.

### 1.3 Что в текущей системе стоит сохранить
- Токены цвета/радиусов/анимаций как подход, `prefers-reduced-motion`, safe-area, `100dvh` — инфраструктура правильная.
- `ft-icon` — 39 stroke-иконок на едином 24px-гриде; расширять его, а не эмодзи.
- Компоненты `score-ring`, `radar`, `flavor-glass`, `match-card` — концептуально нужны, требуют визуального переосмысления.
- Типы пар COMPLEMENT / CONTRAST / CLEANSE / BRIDGE — хорошая основа для семантической цветовой кодировки.

## 2. Что говорят референсы 2024–2026

### 2.1 QR-меню и «гость у стола»
- Все сканы QR — со смартфона; критично: категории/поиск в первом экране, тап-цели ≥ 44 px, загрузка < 2 с на 4G, никаких PDF ([Dineazi](https://dineazi.com/resources/qr-menu-design-tips); [Spilt Milk, Mobile UX for on-the-go diners 2025](https://spiltmilkwebdesign.com/mobile-ux-design-for-on-the-go-diners-expert-tips-for-cafes-in-2025/)).
- **sunday** позиционирует QR-оплату как «discreet, design-led» для fine dining: интерфейс не должен спорить с атмосферой зала, брендинг заведения встраивается в поток; 83% гостей, отсканировавших код, платят через него ([sunday, pay-at-table](https://sundayapp.com/pay-at-table/); [sunday, trends 2025](https://sundayapp.com/trends-in-qr-code-payment-for-restaurants-in-2025/)).
- **Mr Yum** (кейс): раздельные страницы «заведение» и «меню» дали «unnatural flow» с лишними возвратами — их объединили в один экран; ядро — фокус на отдельном блюде, а не на заведении ([Haydn Kwan, Mr Yum UX case study](https://www.haydnkwanux.com/portfolio/mr-yum-ux-case-study/)).
- **Poster POS QR** и **Choice QR** — стандарт рынка СНГ/Казахстана: фото, состав, аллергены, бестселлеры сверху, кастомные темы и цвета заведения, RU/KZ-локализация; Choice интегрируется с Poster, iiko, R-keeper и обещает +20% к среднему чеку через подачу меню ([Poster QR menu](https://joinposter.com/en/tour/addons/qr-menu); [Choice QR](https://choiceqr.com/); [Choice × Poster](https://joinposter.com/en/applications/choice-qr)). Вывод: наш QR-экран должен принимать **брендинг бара** (цвет, логотип), иначе владельцу проще остаться в Choice.

### 2.2 Приложения о напитках
- **Vivino**: ввёл тёмную тему как переключаемую опцию; UX-кейс редизайна фиксирует боли — «taste» и «food pairing» были разнесены по странице, важные действия мелкие и серые; решение — сгруппировать вкус и сочетания вверху страницы, тёмный фон, DM Sans, заливные (filled) иконки под геометрию логотипа ([Noriko Gondo, Vivino UI/UX case study](https://norikogondo.com/vivino/); [Vivino dark theme](https://www.hardreset.info/devices/apps/apps-vivino/enable-dark-theme/)).
- **Untappd**: в 2024 статистика стала динамической и интерактивной с шерингом в одну кнопку; Recappd 2025 превращает годовой отчёт в 32-дневную игру; Untappd for Business в 2025 полностью перерисовал мобильное приложение для управления меню и запустил AI-дизайнер цифрового пивного меню ([Untappd Product Updates](https://updates.untappd.com/); [Next Glass, UfB mobile update](https://www.nextglass.co/news/untappd-for-business-mobile-app-update/); [Craft Brewing Business, AI menu designer](https://www.craftbrewingbusiness.com/business-marketing/untappd-for-business-launches-ai-driven-digital-menu-designer-enjoy-some-design-tips/)). Урок: геймификация уместна в «кабинете» и «академии», не в шапке QR-меню.
- **Hopt**: по этому приложению в поиске найти дизайн-материалов не удалось — источников нет, не цитирую. **Beer Buddy**: отзывы 2025–2026 фиксируют негатив на принудительную 6-секундную анимацию глобуса перед каждым постом и потерю фич в редизайне ([justuseapp, Beer Buddy reviews](https://justuseapp.com/en/app/1487915470/beer-buddy-drink-with-me/reviews)) — антипример «motion ради motion».

### 2.3 Гастрономический / премиальный стиль
- **Resy**: чистая чёрно-белая база, serif/sans-сплит, «Resy Red» + amber/gold токены, типографический и фотографический контраст вместо цвета ([Spectr, Resy design blueprint](https://www.spectr.to/gallery/resy)); критика Pratt 2025 — слабые сигнификаторы у фильтров, неочевидная редактируемость панели «2 гостя, сегодня», разрыв между поиском и discover ([IXD@Pratt, Design critique: Resy](https://ixd.prattsi.org/2025/02/design-critique-resy-ios-app-2/)).
- Обзор лучших ресторанных сайтов 2026: **Noma** — мшисто-зелёный/костяной, тонкий serif-логотип + утилитарный гротеск, «no parallax, no video»; **Death & Co** — тёмный serif «литературный speakeasy», **без фото еды**, ingredient-forward списки коктейлей; **Dishoom**, **Ottolenghi**, **Sweetgreen** — идентичность строится на иллюстрации (вырезная бумага, линейные персонажи-ингредиенты), а не на фото ([Toimi, Best restaurant website designs 2026](https://toimi.pro/blog/best-restaurant-website-designs/)). Для нас ключевое: два сильных прецедента премиального напиточного UI **без фотографии блюд**.
- Тренды 2026: editorial-style сайты, «oversized headlines», типографика как носитель идентичности; для вечерних/upscale концепций — тёмные палитры (charcoal, black, gold, sage), serif возвращается как знак ремесла; для digital-меню — гуманистические гротески ради читаемости ([Northwoods, 2026 trends](https://www.nwsdigital.com/Blog/Website-Design-Trends-for-2026); [Restaurant Branding by Nice, 2026 restaurant design trends](https://restaurantbrandingbynice.com/2026-restaurant-design-trends/)).

### 2.4 Тёмная тема — что говорят данные
NN/g: для людей с нормальным зрением светлая тема выигрывает в точности чтения, преимущество растёт при **мелком** шрифте и сохраняется даже «ночью»; тёмная тема помогает при помутнении хрусталика; рекомендация — давать выбор, не делать тёмную дефолтом для «общих» сайтов ([NN/g, Dark mode vs. light mode](https://www.nngroup.com/articles/dark-mode/)). Следствие для нас: тёмный гостевой экран допустим **только** при крупном шрифте (body ≥ 17 px, второстепенный ≥ 14 px, контраст ≥ 7:1), а кабинет владельца с таблицами цифр должен быть светлым или иметь светлый режим.

### 2.5 Мобильная эргономика
- Тап-цель минимум 1×1 см (≈ 44 px), для главных действий больше (пример Target — 2×2 см), зазор ≈ 2 мм между соседними ([NN/g, Touch target size](https://www.nngroup.com/articles/touch-target-size/)).
- Зона естественного хвата — нижние 25–40% экрана; точность тапа там 96% против 61% в «stretch»-зоне; скрытые меню снижают завершение задач на 21% ([Parachute, Thumb zone guide](https://parachutedesign.ca/blog/thumb-zone-ux/); [Inkbot, Mobile UX for thumbs 2026](https://inkbotdesign.com/mobile-ux/)).

### 2.6 Казахстанский контекст
- **Kaspi.kz** — суперапп с >50% DAU/MAU и 75 транзакций на активного клиента в квартал; с 1 октября 2025 Glovo встроен прямо в Kaspi (раздел «Сервисы»); англоязычного интерфейса нет и не планируется ([Qorus, Kaspi.kz super app](https://www.qorusglobal.com/content/19076-kaspikz-the-super-app-transforming-central-asias-digital-landscape); [Digital Business KZ, Glovo в Kaspi](https://digitalbusiness.kz/2025-10-01/dostavku-edi-glovo-teper-mozhno-zakazivat-v-prilozhenii-kaspi-kz/); [App Store, Kaspi.kz](https://apps.apple.com/us/app/kaspi-kz-%D1%81%D1%83%D0%BF%D0%B5%D1%80%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5/id1195076505)). Привычка аудитории: белые плоские списки, один яркий цвет, крупные цифры в тенге, всё в один-два тапа. Официальной дизайн-системы Kaspi в открытом доступе не нашлось — цифр по её UI не привожу.
- **Wolt**: холодный тёмно-синий + много белого + сдержанный гротеск; в 2025 перерисовали 550+ иконок в единую «playful» систему с жёсткой сеткой и привязкой размеров иконок к кеглю текста (16/12, 20/14, 24/16) ([Wolt, Behind the scenes of Wolt's new icons](https://careers.wolt.com/en/blog/tech/wolt-icon-system-redesign); [dezzayn, Wolt UI](https://dezzayn.com/apps/wolt)).

### 2.7 Кириллические шрифты
Google Fonts даёт фильтр «Cyrillic» — более 200 семейств ([Google Design, Scripting Cyrillic](https://design.google/library/scripting-cyrillic)). Проверено запросом к API (есть блок `/* cyrillic */`): **Unbounded, Golos Text, Inter, Manrope, Onest, Geologica, Roboto Flex, Wix Madefor Display, Tenor Sans, Piazzolla, Literata, Spectral, Playfair Display, Cormorant Garamond**. Отсутствует: Outfit, Plus Jakarta Sans, Fraunces (текущие).

### 2.8 Бутылки без фото блюд
Для упаковки (бутылка, банка) 3D/чистый cutout-PNG выглядит стабильнее и чище фото; прозрачный PNG — стандарт для наложения на любые фоны ([The Kow Company, Rendering vs photography 2026](https://thekowcompany.com/blog/3d-product-rendering-vs-photography-ecommerce); [7CGI, Bottle rendering](https://7cgi.com/blog/bottle-rendering/)). Практический вывод: 17 имеющихся PNG — актив для hero-карточек, но при 100+ сортах и 200+ напитках нужен **системный fallback без картинки**: силуэт тары (бутылка/банка/бокал/кружка) + цвет напитка по SRM/типу + крупная типографика. Иначе каталог будет на 85% «плейсхолдерами».

## 3. Три контрастных направления

Общее для всех трёх: кириллические шрифты; никаких эмодзи (иконки `ft-icon` + иллюстрации); один цвет действия; ответ на пары виден в первом экране; tab bar без FAB; motion — только смысловой (появление ответа, счётчик оценки, переход карточка→деталь).

### Направление A — «Ночная карта» (Dark Editorial Bar)

**Идея.** Экран — как карта напитков в хорошем баре после 20:00: чёрно-графитовый фон, крупный serif-заголовок, бутылка как единственный цветной объект, тонкие линейки-разделители вместо карточек. Ближе всего к Death & Co / Resy / тёмному Vivino.

- **Палитра.** Фон `#0E0D0B` → поверхности `#17150F` / `#1F1B14`; текст `#F3EEE4`, вторичный `#A69E90` (≥ 7:1 на фоне); один акцент — **латунь `#D9A441`** только для действия и оценки; типы пар: complement — `#6FBF8A`, contrast — `#E4714A`, cleanse — `#5FB3D9`, bridge — `#B08BE0` (приглушённые, на 20% заливке). Светлый режим для кабинета владельца: `#F7F5F0` / `#111`.
- **Типографика.** Display — **Playfair Display** или **Piazzolla** (кириллица, оптический размер), кегли 36–44 px на мобильном, `letter-spacing -0.01em`; UI — **Inter** или **Golos Text** 17/15/13, `font-feature-settings: "tnum"` для цен и процентов. Serif/sans-сплит как у Resy.
- **Сетка.** 4-колоночная на 360 px, гаттер 16, вертикальный ритм 8; карточки заменены на строки с 1px разделителями `rgba(255,255,255,.08)`; крупные плитки только у «лучшей пары».
- **Иллюстрации/иконки.** Бутылки PNG на тёмном с мягким цветным «пятном» под тарой (цвет по стилю пива); для сортов без PNG — векторный силуэт тары с заливкой цвета напитка. Блюда — **моно-линейные иконки 1.5px** в стиле гравюры (30–40 штук на категории: мясо на кости, шашлык на шампуре, плов в казане, суши, пицца, бургер, рыба, сыр, острое, десерт). Иконки `ft-icon` в том же стиле.
- **Motion.** Появление ответа: score-кольцо считается 0→92 за 600 ms, строки результата въезжают с задержкой 60 ms; переход карточки бутылки в деталь через `view-transition` (shared element); всё остальное — без анимации.
- **Почему подходит.** Сценарий использования — вечер, бар, приглушённый свет; тёмный UI не «светит в лицо», а бутылки Efes/Kozel/Miller на чёрном выглядят как на рекламном постере. Даёт максимальный контраст с текущим кремовым и сильнее всего «продаёт» со сцены финала.
- **Риски.** NN/g: тёмная тема хуже для мелкого текста — нельзя опускаться ниже 15 px во второстепенном тексте; таблицы владельца нужно делать светлыми; на дешёвых Android с плохими IPS-матрицами чёрный «сереет» — использовать `#0E0D0B`, а не `#000`; serif требует аккуратной кириллицы (Playfair/Piazzolla — ок, но проверить «Қ, Ң, Ү» для казахского).

### Направление B — «Сервис как Kaspi» (Utility Light)

**Идея.** Flavor Tree как утилита внутри привычного казахстанского паттерна: белые плоские списки, одна яркая кнопка, цифры крупно, ноль декора. Гость не «наслаждается дизайном», он за 3 тапа получает «возьми Kozel, 1 750 ₸». Референсы: Kaspi, Wolt, Poster/Choice QR.

- **Палитра.** Фон `#FFFFFF`, подложка списков `#F4F4F2`, текст `#121212` / `#6B6B6B`; **один цвет действия — тёмно-зелёный `#0F7A4D`** (не красный Kaspi и не янтарь — отстройка) либо цвет заведения из настроек (Choice/Poster так делают); оценка пары — числом, не кольцом; типы пар — только цветной текст-лейбл.
- **Типографика.** **Inter** (или Roboto Flex) во всём; вес 600 для названий, 400 для текста; цены 20 px tabular; заголовки 24–28 px, не больше. Никакого второго шрифта.
- **Сетка.** Полноширинные строки-ячейки 64–72 px с иконкой 40 px слева, названием, ценой справа; секции с липкими заголовками (`position: sticky`); чипы-фильтры 40 px в горизонтальной ленте под шапкой.
- **Иллюстрации/иконки.** Плоские **двухцветные иконки блюд** (заливка + 1 акцент) на квадратах 40 px с радиусом 10 — по сути «Kaspi-плитки»; бутылки — cutout PNG на светло-сером; fallback — иконка тары.
- **Motion.** Только системные: skeleton, pull-to-refresh, лёгкий `translateY(8px)` появления списка. Нулевой «character».
- **Почему подходит.** Самая быстрая реализация (2–3 недели реально), максимально знакома владельцам баров и гостям в Алматы/Астане; хорошо масштабируется на 200+ напитков (списки, а не карточки-плакаты); светлая тема выигрывает по читаемости мелкого текста (NN/g); легко принимает брендинг заведения.
- **Риски.** Выглядит как «ещё одно QR-меню» — со сцены финала не отличить от Choice; Efes/премиальность не считываются; основатель, скорее всего, сочтёт скучным. Компенсация — очень сильная типографика цифр и один запоминающийся жест (например, «свайп бутылки к блюду»).

### Направление C — «Печатная карта» (Paper Editorial)

**Идея.** Не тёмный и не «банковский», а как печатное меню brasserie / journal: тёплая бумага без янтаря, чёрная краска, крупные цифры, линейки, гравюрные иллюстрации блюд. Референсы: Dishoom (кино-афиша, много гарнитур), Ottolenghi (вырезная бумага), Sweetgreen (линейные ингредиенты), Noma (утилитарный гротеск + тонкий serif).

- **Палитра.** Бумага `#F4F1EA` (не кремово-жёлтая, а нейтрально-тёплая), поверхности `#FFFFFF`, краска `#161513`, вторичный `#5E5A52`; акцент — **бордо `#7A1F2B`** (винная/ресторанная традиция, контраст 9:1 на бумаге) + серо-зелёный `#4C6B57` для «complement». Янтарь остаётся только в бутылках и в цвете напитка.
- **Типографика.** Display — **Unbounded** (широкий гротеск, кириллица, очень «плакатный», 32–40 px, uppercase для рубрик) в паре с текстовым **Literata** или **Spectral** для описаний; либо инверсия: display **Cormorant Garamond** 44 px + **Manrope** для UI. Цифры оценки — 64–80 px, как цена в винной карте.
- **Сетка.** Двухколоночный «журнальный» ритм на мобильном: левая колонка 96 px под иллюстрацию/бутылку, правая — текст; между блоками 1px чёрные линейки и рубрики-«шапки» с uppercase-трекингом; без скруглённых карточек и теней.
- **Иллюстрации/иконки.** **Гравюрные/линейные иллюстрации блюд** в одной толщине штриха (можно сгенерировать и вручную довести 40–60 штук: бешбармак, казы, шашлык, манты, плов, лагман, самса, суши, пицца, стейк, бургер, сыры, орехи, шоколад); бутылки — PNG с лёгкой полутоновой «бумажной» тенью; иконки UI — тонкий stroke 1.25px.
- **Motion.** Перелистывание: горизонтальный swipe между «блюдо → пара → почему», индикатор-страницы, как разворот меню; появление иллюстрации «прорисовкой» (`stroke-dashoffset`) 400 ms — единственный характерный эффект.
- **Почему подходит.** Отвечает на «нет фото блюд» напрямую — иллюстрация становится фишкой, а не заглушкой; читается днём и вечером; выглядит «ресторанно», а не «стартапно»; объяснительная часть («почему подходит») получает подходящий, журнальный формат.
- **Риски.** Требует 40–60 иллюстраций в едином стиле — производственный риск за 3 недели (реалистично: 25 категорий + общий fallback); может выглядеть статично и «не про технологию» для жюри стартап-конкурса; бумажный фон на OLED ночью ярче тёмного — нужен ночной режим (инверсия в тёмно-графитовый с той же типографикой).

### Рекомендация
Для финала — **направление A для гостевого потока** (QR, подбор, каталог) и **B-подобная светлая утилита для кабинета владельца** внутри той же типографической системы. Иллюстративный подход C стоит взять частично: моно-линейные иконки блюд из C — единственный реалистичный ответ на отсутствие фото, и они одинаково работают на тёмном и светлом.

## 5. Технический план замены (безопасно для Angular-кода)

1. **Шрифты**: заменить ссылку в `index.html` на пары с кириллицей (A: Playfair Display 600/700 + Inter 400/500/600; B: Inter; C: Unbounded 500/700 + Literata 400/500). Подключать с `&subset`-независимым `unicode-range` (Google отдаёт сам), `display=swap`, preconnect.
2. **Токены**: переписать `:root` в `styles.css` — 1 акцент, семантические `--pair-complement/contrast/cleanse/bridge`, `--drink-*` цвета напитков по стилю (lager, dark, wheat, cider, wine-red, wine-white, cocktail, soft, spirit); удалить `--grad-*`, `.glass`, «пузырьки», `body` radial-gradient.
3. **Эмодзи**: удалить поле `emoji` из `Dish` в `core/models.ts` в пользу `icon: DishIconName`; добавить в `ft-icon` 30–40 иконок блюд/тары; флаги кухонь — текстовые лейблы или иконка-кухня.
4. **Компоненты**: `match-card` → строка с числом, `score-ring` → крупная цифра (кольцо оставить только у «лучшей»), `beer-card` → строка + фолбэк-тара, `dish-card` → строка.
5. **Навигация**: tab bar только вне QR-режима; убрать FAB; нижняя контекстная панель действий в гостевом потоке.
6. **Motion**: `view-transition-name` на бутылку, счётчик оценки, reveal 60 ms; остальные `.pop/.reveal` — удалить.
7. **Проверки**: контраст всех текстовых токенов ≥ 4.5:1 (скрипт в CI), Lighthouse mobile ≥ 90, скриншоты 360×800 на всех маршрутах.
