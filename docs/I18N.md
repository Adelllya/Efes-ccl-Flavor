# Языки интерфейса: ru / kk / en

Гостевые экраны Flavor Tree говорят на трёх языках: русский (по умолчанию), казахский (кириллица, живой язык меню
алматинских заведений) и английский. Переключатель **RU / ҚАЗ / EN** стоит в шапке приложения и в шапке гостевого меню
`/m/:slug/:table`. Всё работает без Django — словари вшиты в SPA.

## Что переведено

| Экран | Что именно |
|---|---|
| Оболочка (`app.component.ts`) | вкладки, верхняя навигация, подсказки шапки, подвал, aria-подписи |
| Гостевое меню `/m/:slug/:table` (`venue-menu.page.ts`) | вся обвязка: заголовки, поиск, категории, шторка с подбором, кнопка «Заказать», тост, стандартный слоган заведения |
| `/scan` + чат «Сомелье» (`scan.page.ts`, `sommelier-chat.component.ts`) | шаги, подсказки, чипы-вопросы, ошибки клиента; ответ ИИ — на языке, который вернул сервер |
| Результаты подбора `/pair/:dishId` + карточка пары (`pair-results.page.ts`, `match-card.component.ts`) | контекст (повод, горечь, DNA, заведение), вердикт, причины, разбор по правилам |
| Подписи данных (`core/i18n/data.ts`) | 50 названий блюд, 43 категории, кухни, 13 стилей пива, вкус/вес/жирность/способ готовки, оси профиля, типы пары, вердикты, названия правил, 38 ароматических тегов, 64 вкусовые ноты (задел), причины движка по rule id |
| Клиент ИИ (`ai.service.ts`) | в тело запроса уходит `locale: 'ru' \| 'kk' \| 'en'`; сервер без поля считает `ru`; ответ может содержать `locale` |

## Как это работает

```
core/i18n.service.ts          сервис: сигнал locale, t(), count(), помощники подписей данных
core/i18n/ru.ts               русский словарь интерфейса — ИСТОЧНИК ПРАВДЫ для ключей, тип Dict
core/i18n/kk.ts, en.ts        казахский и английский: `const kk: Dict = {...}` — нет ключа → ошибка компиляции
core/i18n/data.ts             kk/en для подписей данных (русский берётся из data/*.json и движка)
ui/lang-switch.component.ts   переключатель <ft-lang-switch /> (вариант `light` — на цветной подложке)
```

**Определение языка при старте** (`I18nService.detect`): `?lang=kk` в ссылке → `localStorage['ft.locale']` →
`navigator.language` (`kk*` → kk, `en*` → en, иначе ru). Язык из ссылки запоминается — так заведение может печатать
QR с `?lang=kk`. Каждое обращение к `localStorage` обёрнуто в `try/catch` (приватный режим Safari).
Выбор сохраняется и выставляет `<html lang>`; в `index.html` остаётся `lang="ru"` как значение по умолчанию.

**Реактивность.** `locale` — сигнал. `t()` и все помощники читают его внутри, поэтому шаблон (или `computed()`),
вызвавший `t()`, автоматически перерисовывается при смене языка — даже под `OnPush`. По этой же причине здесь **нет
pure-pipe `| translate`**: pipe закэшировал бы строку по ключу и не обновился бы. Правила:

* в шаблоне вызывать `t('key')` напрямую (компоненты держат алиас `readonly t = this.i18n.t`);
* статические списки (вкладки, поводы, шаги сканера) хранят **ключ** словаря, а перевод берут в шаблоне;
* строка, которая нужна вне шаблона (тост, текст для «Поделиться», подпись XP), берётся в момент события —
  внутри `effect()` через `untracked()`, чтобы смена языка не перезапускала эффект.

**Подстановки**: `'{venue} · стол {table}'` → `t('shell.venue.chip', { venue, table })`. Неизвестный плейсхолдер
остаётся как есть. **Откат**: язык → русский → сам ключ (на случай кривого приведения типов; при типизированных словарях
до него не доходит). Пустая строка — допустимое значение (часть фразы, которой в языке нет: «Тағамды суретке түсіріңіз»).

**Числа**: `count(n, 'count.beers')` — ru: один/несколько/много, en: one/other, kk: одна форма (после числительного
множественное число не ставится). Цены и объёмы форматируются как раньше (`ru-RU`), валюта — ₸ на всех языках; на en
`0.5 л` → `0.5 L`.

**Подписи данных**: помощники `dishName()`, `category()`, `cuisineLabel()`, `styleLabel()`, `matchLabel()`, `verdict()`,
`tasteLabel()` … принимают объект/код **и русскую подпись** и на ru возвращают её без изменений — русский всегда
приходит из данных, не из словаря. Нет перевода (новое блюдо, своя категория заведения) → показывается русская подпись.
Название или описание позиции, заданное заведением в кабинете (`item.name`, `item.description`), важнее любого перевода.
Бренды пива не переводятся. Слоган заведения переводится только если это стандартный «Что взять к вашему блюду?».

**Причины движка.** `Contribution.text` — русский текст, который генерирует движок (`pairing-engine.ts` править нельзя:
он зеркалит Python и проверяется по golden). Зато `Contribution.rule` — стабильный id. На kk/en `reason(c)` показывает
одну короткую обобщённую фразу на правило (`RULE_REASONS`), с отдельным вариантом для минуса; для `bridge` — фразу
с переведёнными тегами. Нет шаблона для правила → русский текст. Знак для `intensity` берётся из текста
(`REASON_RULE_BY_RU`), потому что «пиво мощнее блюда» бывает и с маленьким плюсом. Ответ ИИ-сервера (`AiPick.why`)
приходит без rule id — `reasonText()` узнаёт фиксированные фразы движка по тексту; сервер уже перевёл сам → текст
не узнаётся и показывается как есть.

## Как добавить строку

1. Добавьте ключ в `core/i18n/ru.ts` (группы по экранам: `menu.*`, `scan.*`, `chat.*`, `pair.*`, `match.*`, `shell.*`).
2. Сборка упадёт на `kk.ts` и `en.ts` с «missing property» — добавьте перевод в оба.
3. В шаблоне: `{{ t('menu.new.key') }}` или `t('key', { name })`. В классе — `this.t(...)`.

Подпись данных (новое блюдо, стиль, категория) → в `core/i18n/data.ts`, в соответствующую таблицу; ключ — id из
`data/*.json` или русская строка (категории, вердикты). Проверить покрытие после `scripts/build_data.py` можно так:

```sh
cd frontend && node -e "
const fs=require('fs');const d=fs.readFileSync('src/app/core/i18n/data.ts','utf8');
for (const x of JSON.parse(fs.readFileSync('../data/dishes.json'))) if(!d.includes(\"'\"+x.id+\"'\")) console.log('нет перевода блюда:',x.id);
for (const c of new Set(JSON.parse(fs.readFileSync('../data/dishes.json')).map(x=>x.category))) if(!d.includes(\"'\"+c+\"'\")) console.log('нет перевода категории:',c);"
```

## Как добавить язык

1. `Locale` в `i18n.service.ts`: `'ru' | 'kk' | 'en' | 'uz'`; добавьте запись в `LOCALES` (порядок = порядок кнопок).
2. Создайте `core/i18n/uz.ts` с `export const uz: Dict = {...}` — компилятор перечислит все недостающие ключи.
3. Впишите словарь в `DICTS`, добавьте поле `uz` в `L10n` (`data.ts`) — и все таблицы подписей данных попросят перевод.
4. `count()`: опишите правило множественного числа; `detect()`: префикс `navigator.language`.
5. Проверьте ширину шапки на 390px: переключатель растёт на ~34px за кнопку (см. медиа-правила в `app.component.ts`).

## Что намеренно не переведено

* **Кабинет заведения, лендинг для бизнеса, админка, Академия, Flavor DNA, «О проекте», каталог сортов** —
  внутренние и образовательные экраны, аудитория — русскоязычная. Ключи для них не заводились.
* **Описания блюд** (`dish.description`, 50 абзацев) — на kk/en вместо них строка «категория · кухня».
* **Цитаты сомелье** (`pairings_curated.json`) и **уроки/факты** — авторский русский контент.
* **Радар профиля** (`radar.component.ts`), кольцо оценки (`score-ring`), карточки блюд/сортов, страница `/qr/:token` —
  общие компоненты вне гостевого сценария; подписи осей там русские.
* **Заголовки вкладок браузера** (`app.routes.ts` → `title`) и мета-описания в `index.html`.
* **Данные заведения** (город, адрес, слоган кроме стандартного) — как ввёл владелец.
* Ответ ИИ-сомелье и `why`/`reasons` в нём — на стороне сервера (контракт: поле `locale` в запросе).
